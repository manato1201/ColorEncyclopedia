# 6. トラブルと保守

## 症状から探す

| 症状 | 原因の候補 | 確かめ方・直し方 |
|---|---|---|
| `npm run verify` が `[NG] <ファイル>: …` | frontmatter の不備・数値の転記ミス・分類の不一致 | 出力の理由を読む。HSV・Lab は `deriveColorValues` で計算し直す |
| `verify` が「Type Stripping」の警告を出す | Node の実験的な機能(`--experimental-strip-types`)の警告 | 動作には影響しない。Node 22 以上を使う |
| `verify` が「Module type … is not specified」と警告 | `package.json` に `"type": "module"` が無い | 動作はするが、再解析の分だけ遅い(下の既知の問題 3) |
| 一覧に新しい色が出ない | ファイル名が `.md` でない・frontmatter の分類が表と不一致 | `verify` を回す |
| 詳細ページが 404 | `content/` の id(ファイル名)と URL が違う | ファイル名 = id |
| 可視化が出ない | レジストリに、その id が無い | `color-visualizers.ts` の表・`SHAPE_VISUALIZERS` |
| 「立体」にできない | 3D の定義(`shape-3d.ts`・`color-3d.ts`)に、その id が無い | 同左 |
| 学習履歴が消えた | 端末・ブラウザを変えた・データを消した・**検定問題の id を変えた** | JSON の書き出しから復元。id を変えたら、記録は引き継がれない |
| 学習履歴が保存されない | プライベートモードなどで localStorage が使えない | その画面の間だけ有効(仕様) |
| 本文に変な HTML が出る | Markdown の中に HTML を書いた | 本文は `marked` が HTML にして、そのまま埋め込む |
| 文書の検査が落ちる | ソースが変わって、引用・実行例の出力が古い | `python tools/check_docs.py --update` のあと、**差分を読む** |

## 既知の問題・注意(読んで見つけたもの。コードは変えていない)

1. **`deriveThemeFromColor` は、`verify` の検査対象外**。`@/` のパス別名を使うため Node から読み込めず、AA を満たすことの保証(UI の決めごとの核)が、**自動では確かめられていない**。`related-colors.ts` も同様。
2. **本文の HTML は、サニタイズせずに埋め込む**(`dangerouslySetInnerHTML`)。コンテンツがリポジトリの中の信頼できる Markdown だけ、という前提で成り立つ。外部の入力(投稿・取り込み)を足すなら、サニタイズが要る。
3. **`package.json` に `"type": "module"` が無い**ので、`verify` で、TypeScript のファイルを ES モジュールとして**再解析**する(警告と、わずかな遅さ)。
4. **`verify` は、実験的な機能(`--experimental-strip-types`)に依存**する。Node の将来の版で、挙動が変わりうる。
5. **HSV は整数に丸める**ので、HEX → HSV → HEX が元に戻らない色がある(講義 第 1 回)。HEX が正本で、逆の変換はコンテンツに使わない。
6. **`deltaE76` は簡易な指標**(ΔE2000 ではない)。「近い色」の並べ替えには十分だが、知覚差の厳密な比較には使えない。
7. **PCCS のトーンの見本は HSV の自作の目安**で、正式な値ではない。PCCS・マンセルの色立体は計算していない。
8. **検定問題の id を変える・消すと、保存済みの履歴の記録が、読み込まれなくなる**(知らない id は捨てられる)。履歴は端末ごとで、サーバーに無い。
9. **色彩検定の公式範囲との対応は、確認していない**。追加した伝統色(34 件)には、級を付けていない。
10. **`HEX_PATTERN` は小文字も許す**が、`rgbToHex` は大文字で返す。frontmatter に小文字の HEX を書くと、表示と記載で大文字小文字が違うことがある(動作には影響しない)。

## 定期の保守

| いつ | 何を |
|---|---|
| 月に 1 回 | `npm audit`・依存の更新(**Next.js は脆弱性が出やすい**)。更新後に `verify`・`build` |
| Next.js・React を上げたとき | `npm run build` と、主要ページ(`/colors`・`/atlas`・`/exam`)を目で確認 |
| three.js を上げたとき | 「立体」を、複数の図形・色で目で確認(幾何は `verify` が見張る) |
| コンテンツを足したとき | `npm run verify`・`npm run exam-table`(級の表を使うなら) |
| 検定の改定を知ったとき | 公式の最新情報で範囲を確認(このリポジトリは、対応を保証しない) |
| 文書を触ったとき | `python tools/check_docs.py` |

## 直す前の確認

1. **数値を手で書き換えていないか**(HEX から計算したか)。
2. **対応(可視化・立体)を、frontmatter に書いていないか**(レジストリへ)。
3. **検定問題の id を変えていないか**(履歴が切れる)。
4. **確認していないことを、確認済みと書いていないか**(級・出題範囲)。
